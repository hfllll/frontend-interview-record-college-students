❓ **问题 1：如何解决跨域问题**
**问题描述:** 浏览器同源策略导致的接口请求跨域拦截，前端日常开发和上线后如何处理？
**我的解答:**
主要有以下几种主流解决方案：

1. **CORS (跨域资源共享)**：目前最常用的方案，主要依赖后端在响应头中设置 `Access-Control-Allow-Origin` 等字段，允许特定域名访问。
2. **Nginx 反向代理**：生产环境的主流方案。前端请求同源的代理服务器，Nginx 接收请求后转发给真实的后端接口，因为服务器之间没有同源策略限制。
3. **本地开发代理 (Proxy)**：在 Vite 或 Webpack 中配置 `devServer.proxy`，原理同样是在本地启动一个 Node 服务做中间代理。
4. **JSONP**：老旧方案，利用 `<script>` 标签不受同源策略限制的漏洞，但只支持 GET 请求，目前已很少使用。
**知识点标签:** #网络协议 #跨域 #前端工程化

❓ **问题 2：深拷贝 浅拷贝是什么意思**
**问题描述:** 解释 JavaScript 中复杂数据类型（对象、数组）拷贝时的内存层面的区别。
**我的解答:**
这涉及到 JS 的内存管理。基本数据类型存在栈内存，引用数据类型存在堆内存。

* **浅拷贝 (Shallow Copy)**：只复制对象的第一层属性。如果属性是基本类型，拷贝的是值；如果属性是引用类型，拷贝的是其在堆内存中的**引用地址**。因此，新旧对象的子对象会相互影响。
* **深拷贝 (Deep Copy)**：递归复制整个对象树，在堆内存中开辟一块**全新的空间**存放所有属性。拷贝后的新旧对象完全独立，无论怎么嵌套，修改新对象都不会影响原对象。
**知识点标签:** #JavaScript #内存管理 #深浅拷贝

❓ **问题 3：对应方法有哪些**
**问题描述:** 代码层面如何实现浅拷贝和深拷贝？
**我的解答:**
**浅拷贝方法：**

1. `Object.assign(target, ...sources)`
2. 展开语法 (Spread syntax)：`{ ...obj }` 或 `[ ...arr ]`
3. 数组专属：`Array.prototype.slice()` 或 `Array.prototype.concat()`

**深拷贝方法：**

1. **JSON 序列化**：`JSON.parse(JSON.stringify(obj))`。最简单但有缺陷：会忽略函数、`undefined`、`Symbol`，无法处理循环引用和正则/日期对象。
2. **原生 API**：`structuredClone(obj)`。现代浏览器原生支持的深拷贝，能处理多数情况及循环引用，但不支持函数拷贝。
3. **第三方库**：`lodash.cloneDeep(obj)`。企业级开发最常用的稳妥方案。
4. **手写递归**：通过递归遍历属性并判断数据类型来实现，同时需要用 `WeakMap` 记录已拷贝的对象来解决循环引用问题。
**知识点标签:** #JavaScript #手写代码 #API应用

❓ **问题 4：js中数组操作的函数方法有哪些**
**问题描述:** 罗列日常开发中常用的数组原型方法。
**我的解答:**
数组方法可以按照功能分类，并需注意**是否改变原数组**：

* **增删查改（改变原数组）**：
* `push()` / `pop()`：尾部添加/删除
* `unshift()` / `shift()`：头部添加/删除
* `splice()`：任意位置删除/插入/替换
* `reverse()`：反转数组
* `sort()`：排序


* **遍历与映射（不改变原数组）**：
* `forEach()`：单纯遍历
* `map()`：映射生成新数组
* `filter()`：过滤出符合条件的元素组成新数组
* `reduce()`：累加/归并处理


* **查找与判断**：
* `find()` / `findIndex()`：查找首个符合条件的元素/索引
* `includes()`：是否包含特定值
* `some()` / `every()`：是否存在/是否全部满足某条件


* **其他操作**：
* `slice()`：截取数组片段
* `concat()`：合并数组
* `join()`：将数组拼接为字符串
**知识点标签:** #JavaScript #数组API #基础扎实

❓ **问题 5：ws遇到连接不上的问题怎么办**
**问题描述:** 前端在使用 WebSocket 时，遇到连接失败或意外断开该如何排查和处理？
**我的解答:**
分为排查机制与容灾机制：

1. **网络与网关排查**：检查目标服务器是否正常运行；检查 Nginx/网关层是否正确配置了 `Upgrade: websocket` 协议支持，以及超时断开时间是否设置过短。
2. **错误监听**：通过 `ws.onerror` 和 `ws.onclose` 捕获断开状态，给用户适当的 UI 提示（如“网络连接中...”）。
3. **断线重连机制**：在 `onclose` 事件中触发重连逻辑。通常采用**指数退避策略**（如延迟 2s, 4s, 8s 重试），避免服务端雪崩，并设置最大重试次数。
4. **心跳保活 (Heartbeat)**：前端定时（如每 30 秒）向服务端发送一个 `ping` 消息，服务端回复 `pong`。如果超时未收到回复，前端主动销毁当前连接并触发重连，防止死链接。
**知识点标签:** #WebSocket #网络通信 #容灾机制

❓ **问题 6：会不会出现多个ws链接的问题?你是如何解决的**
**问题描述:** 实际场景中，断线重连或组件频繁挂载是否会导致重复创建多个 WebSocket 实例？
**我的解答:**
**会发生。** 常见于两个场景：1. 组件切换导致多次实例化；2. 重连逻辑有漏洞，旧连接处于假死状态还没彻底销毁，就又发起了 `new WebSocket()`。
**我的解决方案：**

1. **单例模式**：将 WebSocket 封装成一个全局单例类或全局状态管理中的唯一对象，确保整个应用生命周期内只有一个活动的实例。
2. **重置与清理**：在发起新的连接前，必须做防御性检查。如果有旧实例，强制调用 `ws.close()` 关闭它，并将其引用置为 `null`，同时清理掉所有绑定的心跳定时器（`clearInterval`）。
3. **生命周期绑定**：如果是组件级的连接，在框架（如 Vue 的 `beforeUnmount`）销毁钩子中，必须手动断开连接并清空资源，防止内存泄漏和幽灵连接。
**知识点标签:** #WebSocket #单例模式 #性能优化

❓ **问题 7：v-if v-show的差别**
**问题描述:** Vue 中控制元素显示隐藏的两个核心指令的区别及应用场景。
**我的解答:**

1. **渲染机制**：
* `v-if` 是真正的条件渲染。它会动态地在 DOM 树中销毁和重建元素及其内部绑定的事件监听器和子组件。条件为假时，DOM 节点根本不存在。
* `v-show` 只是简单地切换元素的 CSS 属性 `display`（`none` 或原始状态），DOM 元素始终保留在页面中。


2. **性能开销**：
* `v-if` 有较高的切换开销（频繁增删 DOM）。
* `v-show` 有较高的初始渲染开销（即便隐藏也会被渲染出来），但切换开销极小。


3. **适用场景**：
* 频繁切换显隐的状态（如 Tab 切换、弹窗显隐），使用 `v-show`。
* 运行时条件极少改变，或初始判断为假不需要加载该模块以节省性能的，使用 `v-if`。
**知识点标签:** #Vue #指令 #渲染机制

❓ **问题 8：浏览器自带的存储方法有哪些**
**问题描述:** 前端本地数据存储方案对比。
**我的解答:**

1. **Cookie**：容量小（约 4KB）。主要用于存储用户鉴权信息（SessionId、Token）。最大特点是每次发起 HTTP 请求都会自动携带在请求头中。
2. **LocalStorage**：容量中等（约 5MB）。永久性本地存储，除非用户手动清除或通过 JS 删除，否则数据一直保留。适合存储用户偏好设置、长期缓存数据。
3. **SessionStorage**：容量同 LocalStorage（约 5MB）。会话级存储。数据仅在当前浏览器标签页有效，标签页或浏览器关闭后数据立即销毁。适合存储单次表单填写过程中的草稿、页面间临时传参。
4. **IndexedDB**：容量大（几十MB甚至更多）。浏览器底层的非关系型数据库。支持事务、索引和异步操作，适合存储大量结构化数据，常用于 PWA 或复杂的离线应用。
**知识点标签:** #浏览器API #本地存储

❓ **问题 9：比如公交车 还有微信支付码 到对方扫码这个过程 如果要实现这个功能 你想怎么实现**
**问题描述:** 场景设计题。描述离线付款码生成到扫码扣款的全链路业务逻辑。
**我的解答:**
这个功能的核心是 **TOTP（基于时间的一次性密码）** 原理和异步消息机制，具体流程实现如下：

1. **前端（用户 APP）生成动态码：**
* 用户打开 APP，前端利用预置的算法机制、用户的身份 Token 和当前时间戳，生成一串加密字符串，并渲染为二维码。
* **关键点**：此过程可以**完全离线**，无需网络请求。二维码有效期极短（如 1 分钟），前端设置定时器自动刷新二维码，防止被截图盗刷。


2. **扫码端（公交车/商户）采集解析：**
* 扫码设备扫描该二维码，读取其中的加密字符串。扫码机本身是必须联网的（或有定时批处理网络）。
* 扫码机将读取到的码字符串、本机的商户 ID、需要扣除的金额组合打包。


3. **服务端鉴权与扣款：**
* 扫码机将数据通过 HTTPS 发送给支付服务端。
* 服务端解密二维码，校验两点：一是二维码是否过期；二是用户对应的账户余额是否充足/状态是否正常。
* 校验通过后，服务端执行扣款事务，并将订单状态落库。


4. **结果双向通知：**
* **商户端**：服务端同步响应扣款结果给扫码机，设备语音播报“支付成功”。
* **用户端**：服务端通过 WebSocket 或长轮询机制，向用户的 APP 主动推送支付成功的回执消息，用户界面的二维码关闭，展示支付凭证。
**知识点标签:** #场景题 #系统设计 #支付安全 #业务逻辑
