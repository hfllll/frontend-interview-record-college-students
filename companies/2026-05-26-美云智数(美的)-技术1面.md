### ❓ 问题 1：Vue2 和 Vue3 的差异

- **问题描述:** 从响应式原理、API 设计、性能、生命周期等角度说说 Vue2 和 Vue3 的区别。
- **我的解答:**
  核心差异从四个维度讲：

  1. **响应式原理**：
  - Vue2 用 `Object.defineProperty` 劫持对象属性的 getter/setter，缺点是无法监听对象新增/删除属性和数组下标变化，需要 `$set` / `$delete` 补救。
  - Vue3 用 `Proxy` 代理整个对象，天然支持对象属性增删和数组索引变化，响应式能力更完整。

  2. **API 设计**：
  - Vue2 是 Options API（data、methods、computed、watch 分块）。
  - Vue3 新增 Composition API（`setup` + `ref`/`reactive`/`computed`/`watch`），同一业务逻辑可以写在一起，方便逻辑复用（抽成 `useXXX` Hook），也更好支持 TypeScript。

  3. **性能优化**：
  - Vue3 做了静态提升、Patch Flag、Block Tree、编译时优化，diff 只关注动态节点，更新粒度更细，性能相比 Vue2 有显著提升。
  - Vue3 的体积也更小，Tree Shaking 友好，按需引入。

  4. **生命周期变化**：
  - `beforeDestroy` → `beforeUnmount`，`destroyed` → `unmounted`
  - Vue3 去掉 `beforeCreate` 和 `created`（setup 本身就代替了这两个阶段）
  - Composition API 中用 `onMounted`、`onUnmounted` 等函数式写法。

  5. **其他**：
  - Vue3 支持 Fragment（多根节点）、Teleport、Suspense 等新特性。
  - Vue3 组合式 API 更适合大型项目和逻辑复用，Vue2 在小型项目里上手更快。

- **知识点标签:** #Vue2 #Vue3 #响应式原理 #CompositionAPI

### ❓ 问题 2：Vue2 的数组是如何实现响应式的？

- **问题描述:** Vue2 用 `Object.defineProperty` 没法监听数组下标变化，那它是怎么做数组响应式的？
- **我的解答:**
  Vue2 对数组做了**特殊处理**——重写了数组原型的 7 个变异方法。

  1. **为什么不能直接监听数组下标**：
  `Object.defineProperty` 理论上可以给数组每个索引加劫持，但性能极差（数组可能几百上千项），而且开发中直接 `arr[0] = xxx` 的方式很少见。Vue2 选择换一条路。

  2. **重写 7 个变异方法**：

  ```js
  const arrayProto = Array.prototype
  const arrayMethods = Object.create(arrayProto)

  const methods = ['push', 'pop', 'shift', 'unshift', 'splice', 'sort', 'reverse']

  methods.forEach(method => {
    arrayMethods[method] = function (...args) {
      const result = arrayProto[method].apply(this, args)
      const ob = this.__ob__
      let inserted
      switch (method) {
        case 'push':
        case 'unshift':
          inserted = args
          break
        case 'splice':
          inserted = args.slice(2)
          break
      }
      if (inserted) ob.observeArray(inserted)  // 新增项也要变响应式
      ob.dep.notify()  // 通知依赖更新
      return result
    }
  })
  ```

  核心思路：当你调用这 7 个方法操作数组时，Vue2 拦截后通知依赖更新。如果是 `push`/`unshift`/`splice` 新增了元素，还会把新增元素也转成响应式。

  3. **不能监听的场景**：
  - 直接通过下标赋值：`arr[0] = 'xx'`——需要用 `Vue.set(arr, 0, 'xx')` 或 `this.$set(arr, 0, 'xx')`
  - 修改 `length`：`arr.length = 0`——需要用 `arr.splice(0)`

  4. **Vue3 的改进**：
  Vue3 用 `Proxy` 代理整个对象，数组下标赋值、`length` 变化都能直接监听到，不再需要重写原型方法。

- **知识点标签:** #Vue2 #数组响应式 #源码原理 #Object.defineProperty

### ❓ 问题 3：Vuex 和 Pinia 的差异

- **问题描述:** Pinia 是 Vue 官方推荐的下一代状态管理，它和 Vuex 有什么区别？为什么选 Pinia？
- **我的解答:**
  从 5 个维度对比：

  1. **API 设计**：
  - Vuex 有 `state`、`getters`、`mutations`、`actions`、`modules` 五个核心概念，概念较多。
  - Pinia 只有 `state`、`getters`、`actions`，去掉了 `mutations`，`actions` 同时支持同步和异步，API 更简洁。

  ```js
  // Vuex 写法
  mutations: { setCount(state, val) { state.count = val } }
  actions: { async fetchCount({ commit }) { commit('setCount', await api()) } }

  // Pinia 写法
  state: () => ({ count: 0 })
  actions: { async fetchCount() { this.count = await api() } }
  ```

  2. **TypeScript 支持**：
  - Vuex 对 TS 的支持比较差，类型推断需要大量额外声明。
  - Pinia 原生就是 TS 优先写的，类型推断完全、IDE 体验好。

  3. **模块机制**：
  - Vuex 是通过 `modules` 嵌套，访问时层级深（`store.state.a.b.xxx`），命名空间容易冲突。
  - Pinia 每个 store 是独立的，不需要 `modules` 嵌套，直接 `useXxxStore()` 即可，天然模块化。

  4. **体积与性能**：
  - Pinia 体积更小（约 1KB vs Vuex 的 3-4KB），且不需要在运行时动态注册模块。
  - 没有 `mutations` 这一层，少了中间环节，理论上更快。

  5. **使用场景**：
  - 老项目、已稳定运行的项目，Vuex 够用不需要迁移。
  - 新项目、TS 项目、复杂项目，直接用 Pinia。

  **一句话总结：**
  Pinia 就是 Vuex 5 的 alpha，更轻、更简洁、TS 更好。官方已经推荐新项目用 Pinia。

- **知识点标签:** #Vuex #Pinia #状态管理 #TypeScript

### ❓ 问题 4：你有封装过什么组件吗？是怎么做封装的？

- **问题描述:** 讲一个你实际封装过的组件，说清楚你的封装思路、对外暴露什么、内部怎么处理。
- **我的解答:**
  封装过不少组件，我拿**文件上传组件**举例说明封装思路。

  1. **分析可变与不可变**：
  - 不变的：上传流程（选择文件 → 校验 → 上传 → 拿结果）
  - 可变的：文件类型限制、大小限制、是否多选、上传地址、上传前后的钩子、UI 样式

  2. **对外暴露的 props 与 events**：

  ```js
  props: {
    accept: { type: String, default: '*' },      // 文件类型
    maxSize: { type: Number, default: 10 },       // 最大大小（MB）
    multiple: { type: Boolean, default: false },  // 是否多选
    action: { type: String, required: true },     // 上传地址
    maxCount: { type: Number, default: 1 },       // 最多上传数量
  }
  // events: @success, @error, @progress, @exceed
  ```

  3. **内部处理**：
  - 文件选择后立即做前端校验（类型、大小、数量），不合法直接 `$emit('error')` 并终止
  - 上传过程中暴露 `@progress` 事件，让父组件可以展示进度条
  - 上传成功后 `$emit('success', { url, name, size })`，把结果透出
  - 组件内部不关心数据怎么存，只负责"拿到文件 → 上传 → 输出结果"

  4. **插槽配合**：
  - 默认插槽：触发上传的 UI（比如按钮、拖拽区）
  - 具名插槽 `tip`：上传提示文案
  - 具名插槽 `file-list`：已上传文件列表展示

  **封装原则：**
  - 组件只做一件事，且做到极致
  - 通过 props 接收配置，通过 events 输出结果，绝不在子组件里直接改父组件数据
  - 预留插槽让使用者控制 UI，不把样式写死

- **知识点标签:** #组件封装 #props #插槽 #设计模式

### ❓ 问题 5：为什么 Vuex 的 mutations 无法做异步请求？

- **问题描述:** Vuex 官方规定 mutations 必须是同步函数，为什么？如果硬要在 mutations 里写异步会发生什么？
- **我的解答:**
  核心原因：**Devtools 的可追踪性**。

  1. **Vuex 的数据流是单向的**：
  ```
  组件 dispatch → Action（异步）→ commit → Mutation（同步）→ State 变更 → 视图更新
  ```

  mutations 是唯一能改 state 的地方，Devtools 会记录每一次 mutation 的快照。如果 mutation 是同步的，快照就是在 state 真正变化那一刻捕获的，可以逐帧回放。

  2. **如果 mutation 里写异步**：

  ```js
  mutations: {
    setUser(state) {
      setTimeout(() => {
        state.user = { name: '张三' }  // 异步更新
      }, 1000)
    }
  }
  ```

  当 Devtools 记录这条 mutation 时，`state.user` 还没变。一秒钟后才变，但 Devtools 的快照已经拍过了，导致：
  - **时间旅行失效**：回退到这一步时 state 和记录不一致
  - **调试混乱**：不知道 state 到底是在哪个时间点变的

  3. **正确做法**：异步逻辑放在 `actions` 里，拿到结果后再 `commit` 同步 mutation：

  ```js
  actions: {
    async fetchUser({ commit }) {
      const user = await api.getUser()  // 异步在 action
      commit('setUser', user)            // mutation 是同步的
    }
  }
  ```

  **一句话总结：**
  不是技术上做不到，是为了保证 Devtools 状态快照的可追溯性和调试体验。把异步交给 action，mutation 管同步更新，边界清晰。

- **知识点标签:** #Vuex #mutations #Devtools #状态管理

### ❓ 问题 6：mutations 如何读取 state？

- **问题描述:** Vuex 的 mutation 函数内部怎么拿到当前 state？
- **我的解答:**
  mutations 的第一个参数就是 `state`，这是 Vuex 内部的约定。

  ```js
  const store = new Vuex.Store({
    state: {
      count: 0,
      user: { name: '张三' }
    },
    mutations: {
      increment(state) {           // 第一个参数就是 state
        state.count++
      },
      addCount(state, payload) {   // 第二个参数是 commit 传过来的 payload
        state.count += payload
      },
      setUser(state, user) {
        state.user = user
      }
    }
  })

  // 组件里调用
  this.$store.commit('increment')
  this.$store.commit('addCount', 10)
  this.$store.commit('setUser', { name: '李四' })
  ```

  底层原理是 Vuex 在注册 mutation 时，用 `call` 把 `store.state` 作为第一个参数传入：

  ```js
  // Vuex 内部简化逻辑
  this._mutations[type].forEach(handler => {
    handler.call(store, store.state, payload)
  })
  ```

  所以 mutation 函数声明时第一个参数必须是 `state`，第二个参数可选，是 `commit` 时传的 `payload`。这是约定好的，不用手动传。

- **知识点标签:** #Vuex #mutations #state #状态管理
